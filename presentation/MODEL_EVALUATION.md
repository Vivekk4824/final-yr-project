# VendorMap Model Evaluation

Audit date: 2026-10-16  
Active model/data version: `manual-142-v2` (`data/catalog.json`)

## Implemented model inventory

- **Production K-Means environmental segmentation:** K=2, trained on 258 usable zone references and 12 GIS/environmental features. It describes environmental similarity; it does not predict vendor success or zone suitability.
- **Production MCDA recommendation engine:** deterministic six-factor ranking with eligibility and capacity constraints. It is a decision-support formula, not a classifier or regressor.
- **AHP utilities:** pairwise-matrix validation, eigenvector weights and consistency-ratio calculation are implemented, but no reviewed real-expert AHP policy exists in `data/policy/mcda_weights.json`. Production therefore uses documented research-policy weights.
- **Experimental supervised suitability models:** Random Forest and XGBoost regressors exist as research demonstrations. Their available labels are explicitly synthetic, so their metrics are proof-of-pipeline results and are not production-performance claims.
- **Allocation optimisation:** Goal Programming/constraint logic is implemented, but it is an optimisation procedure rather than a predictive ML model; classification/regression metrics are not applicable.
- **AI explanations:** Gemini/fallback explanation code explains already-calculated evidence. It does not generate recommendation scores or rankings, and the repository contains no scientific model-quality benchmark for the language output.

## Evaluation method used in this audit

1. The active version and paths were resolved from `data/catalog.json`.
2. K-Means preprocessing was reapplied to the active 258-row feature dataset using `scripts/04_train_kmeans.py`. Metrics were recalculated against the saved active assignments; inertia was recomputed as the sum of squared distances to assignment centroids.
3. MCDA Top-3 results were produced read-only with the current `backend.mcda_engine.recommend` function, `use_live_status=False`, business category `food`, and each documented priority profile. Disabling live status makes the audit reproducible and avoids treating a changing operational snapshot as model quality.
4. Synthetic MSE values were calculated directly from grouped out-of-fold prediction CSVs.
5. Synthetic NDCG@3 was calculated separately for each of the six vendor profiles using graded target relevance, then macro-averaged. No binary threshold was invented.

## Viva Summary

VendorMap’s scientifically valid production evidence is strongest for **cluster structure, repeatability and MCDA transparency**, not predictive accuracy. The active K=2 environmental clustering has a silhouette score of about **0.341**, a Davies–Bouldin index of about **1.465**, and perfect seed stability across the five recorded seeds. This supports using the clusters as broad environmental profiles, but it does not prove that a cluster is suitable or profitable for a vendor.

The recommendation engine is a transparent **MCDA decision-support system**. Its scores are weighted evidence summaries, not probabilities. Its recorded sensitivity analysis is encouraging: rank 1 stayed unchanged in all 224 tested perturbations and mean rank correlation was approximately **0.998**. However, Precision@3, Recall@3, production NDCG@3 and MRR cannot honestly be claimed until independent experts or observed outcomes provide vendor-profile-to-zone relevance judgments.

The Random Forest, XGBoost and AHP demonstration results show that the supervised evaluation pipeline works technically. They use synthetic labels, so values such as RF R² **0.7592** and synthetic NDCG@3 **0.9985** must be presented only as **experimental pipeline validation**, never as real-world model accuracy. For the viva, the defensible conclusion is: the current production system is stable, reproducible and explainable, while real predictive/ranking effectiveness remains future work requiring independent expert labels and field outcomes.
